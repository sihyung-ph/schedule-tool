ℹ 라이브 테이블 검증 — 무엇을 확인하나

EventSchedule 은 행마다 키(EventSchedule_그룹_인덱스)를 가지고, 그 키가 인덱스 번호에 묶여 있습니다. 그래서 인덱스가 한 칸만 밀려도 이미 서비스 중인 행이 다른 이벤트로 덮어써집니다. 이 검증은 그 사고를 추출 전에 잡습니다.
기준: “도래한 이벤트” = 오늘 + 1일까지
시작일 ≤ (오늘 + 1일)인 이벤트 → 키·기간·내용 모두 불변.
게임이 하루 뒤 일정까지 UpComing 으로 미리 노출하므로, 내일 시작하는 이벤트는 이미 플레이어에게 보인 상태입니다. 그래서 오늘이 아니라 내일까지를 잠급니다.
시작일이 모레 이후인 이벤트 = 변경·삭제·추가 모두 자유.
같은 이벤트인지 판정하는 방법
· 의미 = 시작일 + eventDefinitionKey (추출키가 비어 있으면 이벤트 설명으로 대체)
· 레코드 = 1열 키 EventSchedule_그룹_인덱스
이 둘이 어긋나는 것이 곧 인덱스가 바뀐 것입니다.
❌ 위반 — 추출 시 확인창으로 막습니다
도래 이벤트 인덱스 변경같은 이벤트인데 키가 달라짐 → 운영툴 행이 밀려 라이브 기록이 어긋남
키 재사용 충돌같은 키 자리에 다른 이벤트가 들어옴 → 임포트하면 라이브 행이 조용히 덮어써짐 (시작 인덱스를 잘못 잡은 append 에서 주로 발생)
도래 이벤트 내용 변경종료일·기간·타입·설명·조건·spareTime 이 다름 → 진행 중인 이벤트가 바뀜
도래 이벤트 누락추출 날짜범위 안인데 이번 추출에 없음 → 덮어쓸 구간에서 행이 사라짐
과거 이벤트 추가이미 지난 날짜로 행을 새로 만듦 (운영툴엔 없던 것) → “뒤에만 추가” 규칙 위반
⚠ 참고 — 허용되지만 알려줍니다
추출 범위 밖 라이브 행「이 날짜부터·까지」 밖의 과거 행 — 이번 추출이 건드리지 않으므로 무해 (신규만 뽑는 정상 사용법)
미래 이벤트 변동미래 행 수가 달라짐 (정상적인 스케쥴 편집)
신규 이벤트운영툴에 없던 미래 이벤트가 추가됨
그룹 번호 다름추출 그룹이 라이브 도래 행의 그룹과 안 겹침 → 키가 아예 안 부딪힘 (의도한 것인지만 확인)
index 겹침범위 밖 과거 행이 있는데(=뒤에 붙이는 상황) 시작 인덱스가 라이브 최대 index 이하 → 권장 시작값을 알려줍니다
확인 못 한 필드운영툴 데이터의 그 칸이 비어 있어 비교를 못 한 항목 — 시트에서 뒤쪽 컬럼이 잘려 복사되면 흔히 발생. 그 값도 검사받으려면 컬럼까지 포함해 다시 복사
검증하지 않는 것
· 운영툴 데이터에 비어 있는 칸 — “모르는 값”으로 보고 비교에서 빼고, 「확인 못 한 필드」로 알립니다 (빈 칸을 위반으로 세면 잘려 복사된 경우 전부 위반이 됨)
· 미래 이벤트끼리의 차이 — 변경이 자유이므로 개수만 알려줍니다
· 시각(시·분) — 편집기는 자정 기준 날짜 단위라 날짜만 비교
· group·index 자체 — 값 비교 대신 키가 같은 이벤트를 가리키는지로 판정
· 현재 데이터를 안 붙여넣으면 검증 자체가 불가 (추출 시 경고만 뜸)
✅ 안전하게 쓰는 법
1. 시트에서 현재 적용된 EventSchedule 행 전체를 1열 포함해 복사 → 붙여넣기
2. 뒤에만 추가할 때는 「이 날짜부터」를 신규 구간 시작일로, 시작 인덱스를 라이브 최대 index + 1 로
3. 결과가 초록(위반 없음) 인지 확인 후 복사
4. ⚠️ 전체를 다시 뽑을 때는 그룹·시작 인덱스를 라이브와 똑같이 맞춰야 인덱스가 안 밀립니다

ℹ 라이브 검증 — 무엇을 확인하나

운영툴 임포트는 ContentId 레코드를 통째로 교체합니다. 그래서 이미 서비스 중인 시즌이 사라지거나 바뀌면 사고가 납니다. 이 검증은 그 사고를 추출 전에 잡습니다.
추출은 「이 날짜부터」 앞의 기존 시즌을 그대로 이어받아 뒤에 새 시즌을 붙입니다 — 과거를 덮어쓰지 않습니다.
기준: “도래한 시즌” = 오늘 + 1일까지
시작일 ≤ (오늘 + 1일)인 시즌 → 절대 불변.
게임이 하루 뒤 일정까지 UpComing 으로 미리 노출하므로, 내일 시작하는 시즌은 이미 플레이어에게 보인 상태입니다.
시작일이 모레 이후인 시즌 = 변경·삭제·추가 모두 자유.
❌ 위반 — 추출 시 확인창으로 막습니다
도래 시즌 삭제운영툴의 도래한 시즌이 이번 추출에 없음 → 임포트하면 진행/종료된 시즌 기록이 사라짐
도래 시즌 기간 변경시작일은 같은데 종료일이 다름 → 진행 중인 시즌의 기간이 바뀜
과거 시즌 추가이미 지난 날짜로 시즌을 새로 만듦 (운영툴엔 없던 것) → “뒤에만 추가” 규칙 위반
컨텐츠 누락도래한 시즌을 가진 ContentId 가 이번 추출에 아예 없음 → 그 토너의 라이브 기록 소실
편집기에 없는 토너붙여넣은 운영툴 데이터에 편집기가 모르는 스케쥴 토너가 있음 = 누군가 운영툴에서 직접 추가한 것. 추출은 그대로 통과시키지만 앞으로 편집기가 관리하지 못하고, 같은 날짜에 다른 토너를 깔면 조용히 충돌합니다 → 📤 추출 설정에 그 DefKey 를 등록하고 타임라인에 배치하세요. (클랜 고정 베이스처럼 CustomSeasonDatas 가 없는 레코드는 원래 운영툴 관리라 제외)
시즌 기간 겹침같은 토너의 시즌 두 개가 기간이 겹침 → 시즌이 동시에 진행되어 시즌ID·랭킹이 깨짐. 「이 날짜부터」 경계에 걸친 기존 시즌과 새 스케쥴이 부딪힐 때 주로 발생 → 새 스케쥴을 앞 시즌 종료일 이후로 옮기세요
⚠ 참고 — 허용되지만 알려줍니다
미래 시즌 변동미래 시즌 개수가 달라짐 (정상적인 스케쥴 편집)
신규 컨텐츠운영툴에 없던 새 ContentId 가 추가됨
설정값 변경기존 컨텐츠의 설정이 운영툴과 달라짐 — 필드별로 운영툴 값 → 추출 값 표시 (MaxEntryGroupSize·RewardDurationMin·CategoryIds·RegisterBlockedMin·Description·SeasonSetting 등)
이번 추출에 없음도래한 시즌이 없는 컨텐츠가 빠짐 → 영향 없음
검증하지 않는 것
· 고정 베이스(클랜 등 CustomSeasonDatas: null) — 붙여넣은 값이 그대로 통과하므로 비교 대상 아님
· 시즌 시각(시·분) — 편집기는 자정 기준 날짜 단위라 날짜만 비교
· 운영툴 JSON 을 안 붙여넣으면 검증 자체가 불가 (추출 시 경고만 뜸)
✅ 안전하게 쓰는 법
1. 운영툴 [토너먼트 > 데이터 추출]에서 현재 JSON 전체를 복사해 붙여넣기
2. 「기존 컨텐츠 설정 상속」 켜두기 — 기존 토너의 설정값은 운영툴 값을 유지하고 시즌만 갱신
3. 결과가 초록(위반 없음) 인지 확인 후 추출
4. ⚠️ 「이 날짜부터」 필터 주의 — 미래 날짜로 걸면 과거 시즌이 추출에서 빠져 라이브가 깨집니다 (이 검증이 잡아줌)

비우면 전체. 지정 시 시작일이 이 날짜 이후(포함)인 스케쥴만.

📋 토너먼트 추출

같은 토너 DefKey 막대들 → 1개 컨텐츠로 묶임. ContentId = 토너 DefKey 그대로, 각 막대 = CustomSeasonData(시즌). DefKey 는 📤 추출 설정에서 입력.
비우면 전체. 지정 시 시작일이 이 날짜 이후(포함)인 막대만 시즌에 포함.
덮어쓰기가 아니라 이어붙이기입니다 — 이 날짜 앞의 운영툴 기존 시즌은 아래 JSON 에서 그대로 가져와 유지합니다. 경계에 걸쳐 새 시즌과 겹치면 위반으로 잡힙니다.
⚙ 고정값 설정 (모든 스케쥴 토너 공통)
카테고리 ID CategoryIds
토너 그룹 매칭 시 내려올 플레이데이터 키. 쉼표로 여러개. (스케쥴 토너 = Account)
채널 SeparateByUserTags
매칭그룹 필터를 서버 채널(ChannelId)로 사용. 0 = ChannelId 0 (기본 채널). 쉼표로 여러개.
최대 그룹 크기 MaxEntryGroupSize
토너 그룹 하나에 들어갈 최대 인원 수.
전 시즌 보상 개수 RewardClaimableSeasonCount
보상 받을 수 있는 직전 시즌 개수. (약속값 = 1)
보상 수령 보장(분) RewardDurationMin
직전 시즌 종료 후 이 시간까지 보상 수령 보장. 10080분 = 7일.
게임 타이틀 GameTitle
PK 생성용. PK = GP)CONTENT#<GameTitle>.
점수 갱신 타입 SetScoreType
0 = Increase (점수 누적 증가식). 우리는 Increase만 사용.
순환 주기 PeriodUnit
스케쥴 토너는 항상 Custom(6). PeriodValue = 막대 기간(days), 시즌은 CustomSeasonDatas 로 입력됨.
등록 차단(분) 기본값 RegisterBlockedMin
시즌 종료 전 신규 등록을 차단하는 시간(분). 0 = 차단 안함. 예 720 = 종료 12시간 전부터 차단. 📤 추출설정에서 토너별로 덮어쓸 수 있음.
마지막 그룹 채움 기본값 FillInLast…
등록 차단 후 마지막 그룹 채워넣기 (노윈도우 전용). 📤 추출설정에서 토너별 덮어쓰기 가능.
운영툴 현재 JSON 필수 — 고정 베이스 + 라이브 검증
운영툴 [토너먼트 > 데이터 추출/가져오기]에서 JSON 추출 전체를 복사해 여기 붙여넣기. 두 가지로 쓰임: ① 클랜 등 고정 베이스는 그대로 포함 ② 기존 토너와 비교해 라이브 훼손 검증 (도래한 시즌은 불변, 미래 시즌은 변경 허용). 운영툴 값이 바뀌면 다시 붙여넣기.
📋 오프라인 테스트용 JSON (슬림 5필드)
오프라인 클라 테스트용. 대상은 위 조건과 동일(트랙 토너먼트 + 토너먼트 운영툴 체크 + 토너 DefKey), 이 날짜부터 필터도 같이 적용. 고정 베이스는 포함 안 함. 필드 = contentId · description · rewardDurationMin · seasons[{start,end}]

📤 추출 설정의 같은 칸과 같은 값입니다 — 어느 쪽에서 고쳐도 함께 바뀝니다. 타입에 맞는 칸만 보이고, 다른 칸에 값이 남아 있으면 그것도 같이 보입니다.
체크한 스케쥴 중 하나라도 같은 시작일·기간으로 함께 놓이면 통과 (하나도 없으면 경고). 여러 개 선택 가능
체크한 스케쥴과 날짜가 겹치면 경고 (여러 개 가능)
오늘 선처럼 타임라인을 세로로 관통합니다. 시작일은 실선, 종료일은 점선. 이미지 내보내기에도 함께 나갑니다.

🔄 대치 — 다른 스케쥴로 바꾸기

지금 막대:
선택한 막대만 바뀝니다. 각자의 시작일은 그대로 두고 스케쥴만 바꿉니다. 기간은 고른 프리셋을 따르므로 종료일은 달라질 수 있습니다. 타입이 다르면 그 트랙으로 옮겨갑니다.

🔍 라이브 검증 — 기존 일정 vs 이번 추출

초록 그대로 — 기존과 같음 (문제 없음) 파랑 신규 — 기존에 없던 것을 새로 추가 (정상) 노랑 미래 변경·삭제 — 아직 안 보인 구간이라 허용 빨강 문제 — 이미 도래한 것을 바꾸거나 지우거나 끼워넣음 보라 편집기에 없는 토너 — 운영툴에서 직접 추가됨 (토너 검증만) 빗금 — 기간 겹침 세로선 — 오늘 / 도래 경계(오늘+1일)

🔢 스케쥴 개수 계산

기간 안에 시작한 스케쥴만 셉니다. 기간 전에 시작해 걸쳐 있는 것은 제외, 기간 안에서 시작해 기간을 넘겨 끝나는 것은 포함. 흐리게 한 트랙도 포함됩니다.

📌 날짜 메모

날짜 의 메모입니다. 두 가지를 함께 넣을 수 있고, 비우고 저장하면 그 항목만 지워집니다.
